# 开发路线与验收清单

本路线区分“计划实现”和“已验证完成”。只有代码、数据与测试证据齐备后，才将条目标记为完成。

## 阶段 1：项目基础

- [x] 建立仓库说明与 Python 忽略规则
- [x] 建立 FastAPI 最小应用和健康检查接口
- [x] 增加自动化测试（pytest）与 CI（GitHub Actions）
- [x] 补充环境变量示例（.env.example）与日志配置
- [x] 配置集中化（backend/app/config.py）

## 阶段 2：病害检测

- [ ] 确认公开数据集来源、许可和类别映射
- [ ] 编写数据检查与训练/验证/测试划分脚本
- [ ] 建立可复现的 YOLO 基线
- [ ] 记录 mAP@50、mAP@50-95、Precision、Recall
- [ ] 分别验证小目标检测层、注意力模块等改动
- [ ] 保存实验配置、日志和错误样本分析
- [ ] 实现模型加载与图片推理 API

## 阶段 3：农业知识检索

- [ ] 准备可合法使用的农业文本资料并记录来源

- [ ] 构建带标准答案的检索评估集
- [ ] 评估 Hit@K、MRR 等指标，并记录基线

## 阶段 4：图文检索与问答

- [ ] 评估图文模型是否适合所选病害类别

## 阶段 5：前端与交付

- [ ] 使用 Vue 3 构建上传、检测结果和知识问答界面

- [ ] 记录运行环境、测试步骤和已知限制

## 实验记录模板

每次实验至少记录：

- 日期、代码提交版本、随机种子
- 数据集版本、类别数量、数据划分
- 模型结构、预训练权重、训练超参数
- 设备型号、软件版本、推理设置
- 指标定义、测试样本数、实验结果
- 与基线的差异、失败案例和结论

不要在未完成实验前填写或宣传未经验证的性能数字。
